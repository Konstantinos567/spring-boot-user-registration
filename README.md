# User Registration – Simple Web Application

A single-page web application for registering, listing, viewing and deleting users.
Built with **Spring Boot** (REST API), **MySQL** and a **jQuery** single-page frontend.

---

## Features

### Required
- **Homepage** with a menu: *Display Users* and *Register new user*
- **Register new user** form:
    - Name, Surname (mandatory text fields)
    - Gender (mandatory drop-down: M / F)
    - Birthdate (mandatory, jQuery UI datepicker)
    - Work Address, Home Address (optional text areas)
- **Display users** as a list with two columns (Name, Surname)
- Clicking a user opens **all their details in a new browser tab**
- **Delete** a user
- Addresses are stored in a **separate database table**

### Additional
- Validation on both client (HTML5) and server (Bean Validation), with server errors shown under each form field
- Consistent error responses using `ProblemDetail` (RFC 9457): 400, 404, 405, 500
- Confirmation dialog before deleting a user
- "User not found" message when a deleted or non-existent user is opened
- Users list sorted by surname and name
- Protection against XSS when rendering user data
- Docker support: the application and MySQL run with a single command

## Architecture

```
Browser (index.html + app.js, jQuery SPA)
        │   HTTP + JSON  (/api/users)
        ▼
UserController      ← REST endpoints, request validation (@Valid)
        │
UserService         ← business logic, transactions, DTO ↔ entity mapping
        │
UserRepository      ← Spring Data JPA
        │
MySQL               ← tables: users, addresses
```

- The frontend is served by Spring Boot itself from `src/main/resources/static`, so frontend and API share the same origin (no CORS configuration needed).
- The frontend is a **single-page application** with hash-based routing (`#/users`, `#/register`, `#/users/{id}`).
- DTOs (Java records) are used for all requests and responses; JPA entities are never exposed directly.
- Errors are handled centrally in `GlobalExceptionHandler` (`@RestControllerAdvice`).

## Database Schema

```
users                               addresses
─────────────────────────           ───────────────────────────────
id          BIGINT  PK  AI          id            BIGINT  PK  AI
name        VARCHAR(100) NOT NULL   user_id       BIGINT  FK → users.id  NOT NULL
surname     VARCHAR(100) NOT NULL   type          ENUM('HOME','WORK')    NOT NULL
gender      ENUM('M','F') NOT NULL  full_address  VARCHAR(500)           NOT NULL
birthdate   DATE         NOT NULL   UNIQUE (user_id, type)
```

- **One-to-many** relationship: a user has zero, one or two addresses.
- An address row exists only if the user entered that address (no empty rows).
- `UNIQUE (user_id, type)` guarantees at most one HOME and one WORK address per user.
- Deleting a user also deletes their addresses (JPA cascade).

The schema is generated by Hibernate (`spring.jpa.hibernate.ddl-auto=update`).

## REST API

| Method | Endpoint           | Description               | Success          | Errors        |
|--------|--------------------|---------------------------|------------------|---------------|
| GET    | `/api/users`       | List all users (summary)  | 200 OK           |               |
| GET    | `/api/users/{id}`  | Get user details          | 200 OK           | 404           |
| POST   | `/api/users`       | Register a new user       | 201 Created      | 400           |
| DELETE | `/api/users/{id}`  | Delete a user             | 204 No Content   | 404           |

Example request body for `POST /api/users`:

```json
{
  "name": "John",
  "surname": "Smith",
  "gender": "M",
  "birthdate": "1995-04-12",
  "workAddress": "10 Main Street, Athens",
  "homeAddress": null
}
```

Example validation error (400):

```json
{
  "title": "Validation failed",
  "status": 400,
  "detail": "One or more fields are invalid",
  "errors": { "name": "Name is required" }
}
```

## Running the Application

### Option 1: With Docker (recommended)

Requirements: Docker Desktop.

```bash
docker compose up --build
```

Then open **http://localhost:8081**

This starts two containers:
- `db`: MySQL 8.4, with database `user_registration` and a dedicated user `appuser` (privileges only on this database)
- `app`: the Spring Boot application, built with a multi-stage Dockerfile

Stop with `docker compose down` (add `-v` to also delete the database data).

### Option 2: Locally

Requirements: Java 25, MySQL 8.x.

1. Create the database:
```sql
   CREATE DATABASE user_registration;
```
2. Set the database credentials (defaults are in `application.properties`):
```bash
   set DB_USERNAME=your_user
   set DB_PASSWORD=your_password
```
3. Run:
```bash
   mvnw spring-boot:run
```
4. Open **http://localhost:8080**
